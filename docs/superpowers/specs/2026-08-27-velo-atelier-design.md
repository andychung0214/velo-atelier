# Velo Atelier／疾輪工房設計規格

日期：2026-08-27  
狀態：已核准，待實作計畫

## 1. 產品定義

Velo Atelier／疾輪工房是一款桌機瀏覽器優先、支援行動觸控的 3D 公路車訂製模擬遊戲。使用者可直接旋轉、縮放與點選一輛高細節公路車，替換主要零件、調整任意顏色，並在車架加入中文、英文或日文文字。

首版的核心任務是讓使用者在三分鐘內完成一套具有個人識別度的公路車配置，理解各零件用途，並把配置保存在目前瀏覽器。網站必須可部署到 GitHub Pages、Synology Web Station 或其他純靜態網站託管環境。

## 2. 命名與類型

- 英文名稱：Velo Atelier
- 中文名稱：疾輪工房
- 專案資料夾：`velo-atelier`
- 類型：3D 公路車訂製模擬遊戲
- 主要使用者：喜歡公路車、想嘗試塗裝與零件搭配，或正在認識公路車結構的桌機及行動裝置使用者

## 3. 首版範圍

### 3.1 必須包含

- 可旋轉、縮放、重設視角及自動旋轉的 three.js 3D 展台。
- 使用程式化幾何建立完整公路車，包括車架、前叉、輪胎、輪框、花鼓、輻條、碟盤或 C 夾、傳動系統、座艙及配件。
- 車架類型：競賽、空力、耐力。
- 煞車類型：碟煞、C 夾煞，切換時只顯示相符零件。
- 輪組類型：低框輪、刀輪、板輪。
- 傳動類型：電子變速、機械變速。
- 座艙類型：傳統彎把、一體式空力把。
- 把手帶、座墊、水壺架及主要車架管件的獨立選取與顏色設定。
- 點選 3D 零件或控制台項目後顯示名稱、用途與簡短選購提示。
- 車架文字支援中文、英文、日文，並提供至少四種跨語系字體選項。
- 文字顏色與位置預設，可即時更新到車架上。
- 至少三組完整預設配置，讓初次進站者立即看到差異。
- 將目前配置儲存在 `localStorage`，並提供重設功能。
- 桌機、平板與手機三種版面，支援滑鼠、觸控及鍵盤操作。
- WebGL 或儲存功能不可用時提供可理解的降級訊息。

### 3.2 首版不包含

- 真實品牌商標、受限制的車架外觀或第三方未授權模型。
- 尺寸配車、結構強度、相容性或實際購買建議。
- 價格、購物車、會員、雲端同步、多人功能或後端服務。
- 使用者上傳 3D 模型、材質貼圖或任意貼紙定位工具。
- 完整 CAD 精度、物理騎乘模擬或碰撞遊戲玩法。

## 4. 技術方案

### 4.1 已評估方案

1. 完全程式化模型：下載量小、可完整控制零件切換與顏色，但模型細節需要以幾何、材質與燈光細緻補足。
2. 完全採用 glTF 模型：可得到最高視覺上限，但目前沒有可信任且授權明確的完整模型組，也會增加下載量與零件命名依賴。
3. 混合架構：首版以程式化模型完成所有功能，場景與零件目錄保留日後替換 glTF 的邊界。

採用方案 3。首版不下載外部 3D 資產，避免授權及內容交付風險；模型建立函式會依零件群組分離，使未來可逐項替換高精度模型。

### 4.2 執行架構

- `index.html`：語意化頁面骨架、SEO 資訊、WebGL 舞台及控制台容器。
- `styles/`：設計 Token、版面、元件與動態效果樣式。
- `src/data/`：零件目錄、用途說明、預設配置與色票。
- `src/core/`：配置正規化、驗證、序列化與儲存。
- `src/scene/`：three.js 場景、材質、模型建立、文字材質與物件選取。
- `src/ui/`：控制台渲染、事件繫結、狀態同步與無障礙播報。
- `src/app.js`：應用程式入口與模組協調。
- `tests/`：使用 Node.js 內建測試執行器，不依賴大型測試框架。

three.js 透過固定版本 CDN ES Module 載入；網站本身不需要建構步驟。執行與測試使用 `package.json` 腳本提供一致命令。

## 5. 狀態與資料流

唯一配置狀態包含車架類型、煞車、輪組、傳動、座艙、各色彩、車架文字、字體及自動旋轉偏好。所有輸入先交由純函式正規化，再更新狀態。

資料流如下：

1. 啟動時讀取預設配置，再嘗試合併 `localStorage` 中的有效資料。
2. UI 操作或 3D 點選產生明確動作。
3. 狀態層驗證並建立新的配置物件。
4. 場景控制器只更新受影響的零件、材質或文字貼圖。
5. UI 重新呈現選取狀態與零件說明。
6. 合法配置節流後儲存到目前瀏覽器。

場景物件以穩定的 `partId` 連結零件目錄。Raycaster 點選到子網格時向上尋找 `partId`，確保 3D 模型細節不會滲入 UI 邏輯。

## 6. 視覺與互動方向

採用「義式競速海報」方向：象牙白底、酒紅、賽車綠、碳纖黑與鋁銀。字體以窄體拉丁展示字、支援中日文的無襯線內文字及等寬規格字組成。介面使用海報式不對稱構圖、細線規格標籤與大片 3D 展台，不使用泛用漸層、玻璃擬態或大量圓角卡片。

桌機為三欄：品牌／配置摘要、3D 舞台、零件控制台。平板壓縮左欄；手機改為全寬舞台與底部抽屜。唯一醒目元素是一條由車架塗裝延伸到介面的酒紅導引線，用來連結目前選取零件與說明，而不是純裝飾。

場景採工作室棚拍感：柔和環境光、主光、輪廓光、接觸陰影、物理材質與適量抗鋸齒。裝置像素比限制在合理範圍，手機降低陰影解析度；`prefers-reduced-motion` 啟用時停用自動旋轉與非必要轉場。

## 7. 3D 模型設計

- 以公路車常見幾何比例建立車架，車輪共用真實感一致的尺寸基準。
- 車架管件使用沿兩點建立的錐形圓柱；不同車架類型調整管徑、頭管與座叉輪廓。
- 碟煞包含碟盤、卡鉗與鎖點；C 夾煞包含前後夾器，兩者互斥。
- 低框輪、刀輪與板輪有明顯可辨識的框高、輻條或封閉輪面。
- 電子變速與機械變速以後變速器、前變速器與控制盒細節區分。
- 一體式空力把與傳統彎把使用不同把手截面及龍頭結構。
- 材質至少區分烤漆、碳纖維、陽極金屬、霧面橡膠及半透明塑料。
- Canvas 文字材質產生雙側車架標字；空白文字時隱藏，不保留透明點選面。

## 8. 錯誤與降級處理

- WebGL 建立失敗：保留頁面內容與控制說明，舞台顯示瀏覽器／硬體建議。
- CDN 載入失敗：顯示 three.js 載入失敗及重新整理提示，其他靜態內容仍可閱讀。
- `localStorage` 被停用或容量不足：設定仍可在目前分頁操作，並以非阻斷狀態訊息告知未儲存。
- 儲存內容格式錯誤：忽略無效欄位並回到安全預設，不執行任意內容。
- Canvas 字體缺字：回退到系統 CJK 無襯線字體，仍顯示原始文字。

## 9. 測試策略

自動測試使用 `node:test`，至少涵蓋：

- 零件目錄 ID、分類與說明完整性。
- 預設配置及所有可選值合法性。
- 配置正規化、色碼驗證與未知欄位忽略。
- 中文、英文、日文文字保留、長度限制與危險控制字元處理。
- 儲存序列化、版本遷移與損壞資料回復。
- HTML 必要控制、SEO、跳至主要內容及狀態播報區契約。
- CSS 的三組 RWD 斷點、焦點樣式及減少動態效果契約。

瀏覽器驗證至少包含：桌機 1440×900、平板 834×1112、手機 390×844；確認模型顯示、旋轉、縮放、點選、零件切換、顏色、跨語系文字、重新載入保存、鍵盤焦點及瀏覽器控制台無未處理錯誤。

## 10. 驗收條件

- 從靜態伺服器開啟首頁後，在支援 WebGL 的主流瀏覽器顯示完整公路車。
- 使用者能以滑鼠或單指旋轉，以滾輪、手勢或按鈕縮放。
- 碟煞／C 夾煞、三種輪組、兩種傳動與兩種座艙切換會即時反映在模型。
- 至少八個可辨識零件群組可獨立選色，且所有 HTML 色彩輸入可用。
- 3D 點選與控制台選取都能開啟正確用途說明並同步高亮。
- 中文、英文、日文車架文字及四種字體能顯示並在重新載入後保留。
- 三個預設配置可一鍵套用，重設可回到預設狀態。
- 自動測試全部通過，三種目標尺寸完成實際瀏覽器驗證。
- README、`docs/PLAN.md`、`docs/ART-DIRECTION.md`、`docs/TEST-PLAN.md`、`.gitignore`、MIT `LICENSE` 與 `CONTRIBUTING.md` 完整存在。
- 儲存庫不包含 `.env`、憑證、token 或私人金鑰。

## 11. 已知限制

- 程式化模型追求產品展示級辨識度與材質表現，不宣稱達到品牌 CAD 或攝影掃描精度。
- three.js 由固定版本 CDN 載入，首次使用需要網路；靜態內容與錯誤說明不受影響。
- 配置只儲存在目前瀏覽器，不跨裝置同步。
- 顯示的零件相容性為互動示範，不代表真實產品的尺寸與機械相容性。
